# Design rounds

How the design step runs, the prompt for each round, and a log of what was decided. Each round starts in a fresh Claude Code session: paste that round's prompt.

## How it works

- Claude Code creates and updates a **Design artifact** (a canvas of artboards on claude.ai) from `DESIGN-BRIEF.md` and `sample-data.json`. It reads the repo directly; nothing is copied by hand.
- The owner reviews each round on a laptop and on a phone, harshly, and says what works and what doesn't. Claude iterates until the round is signed off. Only then the next round.
- Before round 1: list the account's design systems. Don't use one from another project; this design defines its own look.
- After each round: add a row to the log below, and a line to `AI-LOG.md` for anything rejected or reworked.

## What to judge every round

- Does the reviewer see their claim's status and what needs them first?
- Can you tell the agent's values from your own at a glance?
- Does it read at a glance, on the phone too? Density, type, spacing, hierarchy.
- Does it look designed, not like a default component library?
- Could it be built with a small set of tokens?

## Design rules from the owner (round 1, apply from round 2 on)

- **Layout is list-detail (direction G).** On laptop: a compact field list on the left (the overview), one field open in the middle, its source document on the right (always shown). On phone: the list is the main screen; tapping a row opens the field full screen with previous/next arrows and a bottom action bar.
- **Sections collapse but still show what's left.** A collapsed section keeps its problem rows visible; the header count (decided / total, orange count = needs you) says what is left. No "+ N more to check" line (dropped in round 3, 2026-11-19: it repeated the header count). Older frames still draw it; ignore it there.
- **Less text.** Tags instead of sentences ("Changed after you", "Low 38%", "Empty", "Not in source", "Blocks sign-off"). Longer content (agent's reason, history, full citation) goes in collapsible sections, closed by default unless it matters for this field.
- **Buttons.** The decisions (Accept, Correct, Reject, Use new / Keep mine; "Reject" opens an empty input plus a one-line reason) are an icon plus one word. Navigation, skip, undo and hide are icon-only, with a tooltip and an `aria-label`. Keyboard hints on laptop: J/K move, A/C/R decide, S skips.
- **Decide in the open field only.** No Accept button on list rows: the reviewer must see the cited text before deciding.
- **Colour has one meaning each.** Orange only for "needs you"; blue only for "yours" (decided values, the "You · accepted" pill as a light tint, progress). Blue is "you": solid blue fill for the action you take (primary buttons), light blue tint with a solid border for what you decided (the pill, your values). A state is never drawn as a solid fill, so "press this" and "this is yours" never look alike. Everything else is navy or neutral blue-grey. State is never shown by colour alone (shape or text too).
- **Compact, calm, modern.** Rows about 36–40 px on laptop, 48–52 px on phone. Few borders; whitespace and subtle backgrounds separate areas. Clickable things look clickable (hover, selected, focus, pressed).
- **Look from the MarvelX site (round 2).** Cool blue-grey ground, blue-navy ink, one blue accent (their indigo, shifted bluer and calmer). Serif for the open field's name and state headlines, Inter for sentences, mono for values, amounts, IDs, scores, citations and uppercase section labels. No dashed lines anywhere (round 2, step 2): dashed reads as "empty slot". Not taken: marketing-size cards and shadows, mono for running text, scores as "0.97", accent colour on everything.
- **Field card (round 2, revised in step 2).** Name (serif) with problem tags → the value box → one line under it: the decision pill, then who/when and confidence as grey text ("Not decided · Agent · found 10:06 · High 93%") → actions → collapsed details (why it changed, your reason, history only when there is more than one version). After a decision: Correct and Reject stay, Undo is an icon. No confidence colours or meters.
  - **Value box holds only the value.** Not decided: white box, plain grey border. Yours: blue tint. The agent's earlier value you corrected or replaced: greyed, no pill. An input while correcting, same size as the value.
  - **A pill shows only the decision.** Grey "Not decided", or blue "You · accepted / corrected / replaced 10:06" with its own icon (✓ ✎ ⇄), so the decision never relies on colour. Who and when is never a pill.
  - **Confidence** sits on the agent line; Low is an orange tag next to the name instead.
  - **Tags.** Orange = still needs you. Grey = a problem you have already decided (e.g. "Low 41%" on a replaced value).
  - **Before → after** (yours vs the agent's): side by side for money, dates, times, numbers and yes/no (always short); stacked with ↓ for text and long text, on laptop too (side by side wraps from about 20 characters).
  - **Status glyphs: one circle family (step 2).** Grey ring = not decided; blue circle with ✓ = yours (accepted, corrected, replaced); orange circle with ! = needs you (problems, changed after you, step warnings, the "Needs you" filter and section counts). The mark carries the meaning, colour repeats it. Orange tags carry no glyph. The triangle is only for real errors (save failed, failed run step, backend unreachable).
  - **No saving state.** A decision shows as decided at once; if the save fails, the field goes back to how it was with "Couldn't save. Try again".
- **Evidence lives in the document panel (laptop).** The card describes the value; the panel on the right shows the evidence: the open field's document with the cited text highlighted, and the "No source" and "not found in the cited text" notes. The panel is always shown; no hide/show, no "Back to cited text" (step 2c: out of scope). No source link on the card. The orange tags ("No source", "Not in source") stay on the card and in the list. On phone (no panel) the quote card under the value opens the bottom sheet.
- **Value size follows the field's type, never its length (round 2).** Money, date, time, number, yes/no: mono 22 px, one line. Text: mono 18 px, up to 2 lines. Long text: Inter 14 px, 4 lines, then "Show all". The same size in every state (one box or two, and the input while correcting), so a revision never resizes a value. Why: all 38 money, date, time, number and yes/no values in the fixtures fit in 12 characters, so the large size never wraps where comparing matters most (€ 3,605.80 → € 4,415.30); text values run to 57 characters and long text to 533. Sizing by length would make a value jump size when the agent revises it. Codes stored as text (registrations, invoice numbers) get the text size.
- **Content is real.** Use only text from `sample-data.json`. Never invent document lines, agent reasons or fields.

Background: `plans/design/RESEARCH.md` (what similar products do and why G won).
